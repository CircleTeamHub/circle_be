# 四档会员权限后端设计

## 目标

后端成为会员套餐、有效期、权益和配额的唯一事实源。App 负责展示，所有创建与加入行为必须由后端在真实写路径中强制校验。会员由客服在管理端人工开通或补差价升级，不在 App 内产生交易。

> 配额值以 `MEMBERSHIP_CATALOG`（`src/membership/membership.catalog.ts`，`/membership/plans` 返回、各写路径强制）为唯一事实源，本表与之逐项对齐。普通用户不可建群，「单群人数」配额对其不适用（catalog 里的 100 仅作默认底值）。首版**没有**「已创建群」配额，创建路径也不做该维度限制，故本表不再列该列。

语音转文字对所有用户开放，不属于会员限制。首版没有头像框或动态头像权益。

## 身份权益

- 名字颜色：普通默认、白银银色、黄金金色、钻石七彩、超级专属流光。
- 会员徽章：白银、黄金、钻石、超级永久。
- 高级圈子：现有 `joinVipRestriction` 统一限制为 1-4，并使用有效会员等级校验。
- 靓号赠送：首次达到钻石发放一张普通靓号权益凭证；首次达到超级发放一张高级靓号权益凭证。凭证按用户和类型唯一，重复请求或续期不会重复发放。

## 有效期和兼容

`User.vipLevel` 保留为 0-4，新增 `vipExpiresAt`。白银、黄金、钻石按服务器日历月从客服开通时间计算；超级会员的到期时间为 `null`。历史 1-3 级且没有到期时间的数据视为兼容期内有效，历史 4/5 级映射为超级会员。

本次会员语义变更使用协调维护窗口部署，不做蓝绿重叠：发布时同时启用 `RELEASE_DOWNTIME=1` 和 `RELEASE_IRREVERSIBLE_MIGRATION=1`，停止旧 API 实例、定时任务和直接写库脚本，完成备份后执行正式 Prisma 迁移，再部署并启动新版本。迁移将历史 `vipLevel > 4` 映射为 4，将 `joinVipRestriction <= 0` 映射为 `null`、大于 4 映射为 4，然后添加 `CHECK (vipLevel BETWEEN 0 AND 4)` 与可空的圈子门槛 1-4 约束。月度有效期使用 UTC 日历月并将月末夹到目标月最后一天，覆盖 1 月 31 日和闰年边界。

约束应用后，旧版本会尝试写入不再合法的数据，因此回滚下限是该会员版本；应用回滚必须使用保留新会员写入契约的修复版本，不能直接恢复旧二进制。

生产发布脚本必须识别不可逆迁移边界：迁移失败时可恢复旧版本；迁移一旦成功，后续启动、健康检查、代理切换、状态写入或烟测失败都不得自动重启旧二进制，只能保持维护状态等待向前修复，或先从迁移前备份恢复数据库再恢复旧版本。

本版本携带不可逆迁移标记。`v*` tag 的自动部署检测到标记后必须 fail closed，不允许使用无参数的 tag-push 路径；运维人员使用同一 tag 手动 dispatch，并同时确认 downtime 与 irreversible migration。手动路径缺任一确认也必须在连接服务器前失败。部署成功后的后续版本移除标记。

所有授权读取使用“有效等级”：已到期的 1-3 级按普通用户处理。API、徽章、圈子加入限制和广场限制不能直接信任原始 `vipLevel`。

到期或降级采用软降级：不删除已有圈子、成员、笔记，也不踢出群；当现有数量达到或超过新配额时阻止新增。

## 客服开通与升级

新增仅 `JwtGuard + AdminGuard` 可访问的管理接口。请求包含目标用户、目标等级、UUID 幂等键和可选备注。只允许从当前有效等级升级到更高等级；已过期用户可重新开通任意等级。

事务内完成：锁定目标用户、校验幂等键、计算服务器到期时间、写用户会员状态、写会员发放审计记录、发放一次性靓号凭证。事务提交后再失效缓存、发送实时事件和系统通知。通知失败不回滚已成功开通。

幂等重放返回第一次的发放结果，但不能再次失效缓存、发送实时事件或通知。

旧的用户积分兑换接口移除。套餐查询返回价格、有效期、展示值和实际配额；`GET /membership/me` 返回当前有效身份、到期时间、权益和凭证。

仓库内所有直接会员写入脚本必须改为调用管理接口或复用同一发放服务；测试数据和徽章脚本统一使用 0-4。不能保留绕过审计、幂等、有效期和权益凭证的 `vipLevel` 直写入口。

## 强制校验点

### 圈子和群聊

- 创建圈子：同一事务中锁定用户，校验有效会员、已创建圈子数、已加入群数和请求的单群人数上限。未传 `maxMembers` 时使用档位上限，不能留下 `null` 无限容量。
- 加入圈子：用户申请时可先校验，最终在申请批准和管理员直邀激活成员的事务内再次校验已加入群配额，防止并发和旁路。
- 最终激活同时重新校验圈子的会员、信用和靓号门槛；申请后会员到期不能绕过门槛。
- 批量邀请：按稳定顺序获取所有目标用户的全局 advisory lock，再逐个校验；任何目标超额或不满足圈子门槛时整个批次失败，避免部分同步。不同圈子的并发邀请也必须共享同一用户锁。
- 圈子等级限制：创建者不能设置高于自己有效等级的会员门槛。

已加入群数量定义为本地 `CircleMember.status = ACTIVE`，包含自己创建的圈子。临时聊天是有时限的访客房间，不计入长期会员群聊配额。

### 笔记

新建笔记和收藏复制笔记都在 Serializable 事务内获取同一用户 advisory lock，并统计 `status != DELETED` 的笔记数。软删除会释放容量。重复收藏已有副本不消耗新配额。

### 城市筛选

保留现有 GET feed 给旧客户端和小筛选，并新增 body-based 搜索接口承载城市与圈子数组。服务端先做绝对输入上限，再按用户有效会员等级校验去重后的城市数量。前端显示“不限”不代表后端无界；超级会员实际最多 1000 个城市，不能依赖超长 URL 查询串。

## 客户端身份契约

`/auth/me`、会员实时事件和用户资料摘要返回有效 `vipLevel` 与 `vipExpiresAt`。公开用户资料和广场作者额外返回稳定的会员外观对象（有效档位、名字颜色、徽章），让客户端可以可靠渲染其他用户的身份；不暴露会员审计记录或客服备注。

任何缓存会员结果的路径都必须把 TTL 夹到到期时间，或在缓存命中时重新计算有效等级；到期瞬间不能继续返回付费身份。测试使用假时间跨过到期边界。

会员策略拆为无 Realtime 依赖的 `MembershipPolicyModule`。业务模块只依赖该模块；`MembershipModule` 在其上编排客服开通、通知与实时事件，避免 Realtime 和会员模块循环依赖。

## 并发和安全

- 配额的“统计 + 写入”必须位于同一 Serializable 事务或同一用户 advisory lock 下。
- 同一个用户在建群、加群、建笔记时使用同一类稳定 advisory lock；批量锁按用户 ID 排序，避免死锁。
- 客服开通必须有唯一幂等键，重复请求返回第一次结果，不重复发放权益或通知。
- 所有管理入参通过 DTO 验证，管理接口必须要求 ADMIN audience。
- 审计记录保存操作人、目标用户、前后等级、前后到期时间和备注，不保存微信、支付宝或转账信息。
