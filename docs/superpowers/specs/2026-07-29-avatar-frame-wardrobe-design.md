# 头像框装扮系统设计

## 目标

把现有按会员等级在客户端临时推导的头像框，升级为完整的装扮资产系统：

- 个人页紫色会员区域的“我的徽章”改为“我的装扮”。
- “我的装扮”提供“我的徽章”和“我的头像框”两个入口。
- 一个用户可同时拥有多个头像框，可查看每个头像框详情、切换当前佩戴，或选择不佩戴。
- 头像框来源首期支持会员等级累计解锁和管理员发放。
- 会员到期后，仅由会员资格提供的头像框立即失效；若正在佩戴，对外自动显示为无头像框。
- 管理后台提供头像框发放和撤销入口，所有操作可审计。

首期不接商城购买，也不提供管理后台头像框目录 CRUD。目录先包含现有钻石和超级会员素材，并允许后续通过迁移加入远程素材。

## 已确认的产品规则

1. 高级会员累计解锁低档位头像框。例如超级会员可同时使用钻石和超级头像框。
2. 会员来源的头像框只在对应会员资格有效时可用。会员整体到期后立即失效。
3. 管理员可永久或限时发放头像框，也可撤销某次发放。
4. 同一头像框只要仍存在任一有效来源（有效会员资格或至少一笔有效管理员发放），用户就继续拥有它。
5. 用户只能佩戴当前可用的头像框。选择 `null` 表示不佩戴。迁移完成后，首次获得新头像框或会员升级都只增加库存，绝不自动佩戴或覆盖用户的“无头像框”选择。
6. 当前选择失去资格时，读取公开外观必须立即解析为无头像框，且该选择不能在以后续费或重新发放时自动复活。再次获得资格后仍需用户重新点击佩戴。
7. 隐藏/更换是账号级设置，跨设备同步，并影响个人资料、聊天、朋友圈/广场等所有头像框展示面。

## 数据模型

### `AvatarFrameAsset`

头像框目录：

- `id`: UUID。
- `key`: 稳定唯一键，例如 `membership-diamond`。
- `name`: 展示名称。
- `description`: 详情说明。
- `imageUrl`: 可空；远程素材 URL。内置素材通过 `key` 映射客户端本地资源。
- `minimumVipLevel`: 可空；非空时表示会员累计解锁门槛。
- `isActive`: 是否仍可使用。停用立即阻止新发放/新选择，并使已有发放和当前佩戴不再生效；重新启用只恢复库存资格，不自动恢复以前的佩戴选择。
- `sortOrder`: 排序。
- `createdAt`、`updatedAt`。

首期迁移写入钻石和超级两个内置头像框。内置资源由移动端使用 `key` 映射现有 `assets/frames/*.png`，避免依赖未部署的 CDN URL。

### `UserAvatarFrameGrant`

管理员发放记录：

- `id`: UUID。
- `userId`、`frameId`。
- `operatorUserId`。
- `idempotencyKey`: 全局唯一，防止重复提交。
- `reason`: 必填审计原因。
- `expiresAt`: 可空，空表示永久。
- `revokedAt`、`revokedByUserId`、`revokeReason`。
- `createdAt`、`updatedAt`。

有效管理员来源定义为：未撤销，且 `expiresAt` 为空或晚于当前时间。

### `User.selectedAvatarFrameId` 与 `selectedAvatarFrameExpiresAt`

`selectedAvatarFrameId` 为可空外键，`null` 表示明确不佩戴。`selectedAvatarFrameExpiresAt` 是选择时有效来源的连续资格截止快照：任一来源永久有效时为空，否则取全部当前有效来源的最晚到期时间。

公开解析必须同时验证目录 active、当前仍有有效来源，以及截止快照未过期。会员续期或新管理员发放只有在原选择在操作发生时仍有效，才可把截止快照向后延长；若选择已经过期，不更新快照，也不自动重新佩戴。

每次减少资格的状态变更——管理员撤销、会员等级降低/替换、目录停用——都必须在同一事务中依据“剩余且连续有效”的来源重新计算当前选择的截止快照。没有剩余来源时清空两个选择字段；只剩有限期来源时，即使原快照为 `null` 或更晚，也要收紧为这些来源的实际最晚到期时间。这样撤销永久来源后不会遗留 `null`，也不会让以后续费把旧选择复活。单纯时间流逝由已保存的有限截止快照处理。定时清理只用于数据卫生，公开正确性不依赖清理任务。

保留现有 `User.avatarFrame` 字段作为旧字段兼容，不再将其作为会员框或新选择的真相来源。

## 后端边界

新增独立 `AvatarFrameModule`，避免把库存和管理员逻辑塞入 `UserService` 或 `MembershipService`。

### 资格解析

`AvatarFrameService` 提供：

- 列出当前用户全部可用头像框，并合并会员与管理员来源。
- 验证并设置当前佩戴。
- 批量解析用户的有效会员等级和当前有效头像框，供聊天/列表避免 N+1。
- 为公开用户、好友、动态作者和当前用户序列化统一的外观字段。

解析选中头像框时必须同时验证：

- 素材仍为 active；
- `minimumVipLevel` 对应的有效会员等级满足门槛，或存在有效管理员发放；
- 选中 ID 确实属于目录。
- `selectedAvatarFrameExpiresAt` 为空或晚于当前时间。

### 用户 API

- `GET /avatar-frames/me`
  - 返回 `equippedFrameId`、`items[]`。
  - `equippedFrameId` 只表示当前实际生效的佩戴；过期、停用或失去来源时返回 `null`，不暴露内部陈旧选择。
  - 每项包含素材详情、`ownedSources`、`availableUntil`、`equipped`。
  - `ownedSources` 是结构化数组：
    - 会员来源：`{ type: "MEMBERSHIP", minimumVipLevel, expiresAt }`。
    - 管理员来源：`{ type: "ADMIN", grantId, expiresAt }`。
  - 用户库存只返回当前有效来源，不返回已撤销记录。`availableUntil` 在任一来源永久/终身有效时为 `null`，否则取有效来源的最晚到期时间。
- `PUT /avatar-frames/me/equipped`
  - body: `{ frameId: string | null }`。
  - `null` 取消佩戴；无资格 ID 返回稳定业务错误码。
- `POST /user/appearances`
  - body: `{ ids: string[] }`，有数量上限和去重。
  - 返回用户 ID 到 `{ vipLevel, avatarFrame }` 的映射；`avatarFrame` 包含 `id`、`key`、`imageUrl`，无有效佩戴则为 `null`。

公开用户响应新增同形的 `avatarFrameAppearance`。旧 `avatarFrame` URL 字段暂时保留，避免破坏旧客户端。

### 管理 API

- `GET /admin/avatar-frames/assets`
- `GET /admin/avatar-frames/users/:userId`
- `POST /admin/avatar-frames/users/:userId/grants`
  - body: `frameId`、`expiresAt?`、`reason`、`idempotencyKey`。
- `POST /admin/avatar-frames/grants/:grantId/revoke`
  - body: `reason`。

发放、撤销和选择更新使用事务。管理员操作写严格审计记录；幂等键重放相同请求返回原结果，复用到不同请求返回冲突。

### 失效与实时刷新

会员发放、头像框发放/撤销、用户更换佩戴后：

- 失效用户热缓存；
- 广播资料摘要刷新；
- 移动端更新当前用户或批量外观缓存。

即使缓存失效或后台清理失败，公开读取仍以当前时间和有效会员等级重新解析，不能继续显示已过期头像框。

## 移动端

### 导航层级

- 个人页紫色区域：`我的装扮`。
- `我的装扮` 列表页：
  - `我的徽章` → 复用现有 `MyIconsScreen`。
  - `我的头像框` → 新头像框收藏页。
- 头像框收藏页：
  - 顶部实时预览当前头像和佩戴框。
  - 第一项为“无头像框”。
  - 其余为全部当前可用头像框，展示名称、来源摘要、到期状态和当前佩戴标识。
  - 点击具体头像框进入详情。
- 头像框详情页：
  - 大图头像预览。
  - 名称、说明、获得方式、有效期、佩戴状态。
  - 主按钮为“佩戴此头像框”；已佩戴时提供“取消佩戴”。

### 客户端外观模型

新增 `AvatarFrameAppearance` 与统一 `resolveAvatarFrameSource`：

- 内置 `key` 映射本地 PNG。
- 有 `imageUrl` 的扩展素材使用远程 URL。
- 所有 `Avatar` 调用使用服务端解析后的当前外观，不再单独只按 `vipLevel` 推导框。

聊天等仅有用户 ID 的场景使用新的批量外观缓存。会员名字特效继续读取同一批量响应中的 `vipLevel`，从而避免并行维护两个容易漂移的缓存。

### 保存与错误

- 佩戴/取消请求使用同步点击守卫，防止快速重复提交。
- 保存成功后立即更新 auth store、外观缓存和页面预览。
- 保存失败保留原服务端选中状态，显示可重试错误，不做错误的乐观展示。
- 库存加载失败显示重试状态；空库存仍显示“无头像框”。

## 管理后台

用户详情增加“头像框”卡片：

- 当前佩戴头像框。
- 会员累计解锁项（只读）。
- 管理员发放记录、有效期、状态和操作人。
- 发放按钮：选择目录项、选择永久或到期时间、填写必填原因。
- 有效管理员发放可撤销，撤销需要二次确认和必填原因。

成功后刷新用户头像框查询和最近 Admin 操作记录。错误提示使用后端稳定错误消息，不在前端伪造成功。

## 迁移与兼容

1. 创建目录、发放表、`selectedAvatarFrameId` 和 `selectedAvatarFrameExpiresAt`。
2. 种子式迁移插入钻石、超级内置头像框。
3. 现有有效钻石/超级会员不写发放行，资格由有效会员等级动态累计解析。
4. 为保持现有视觉，迁移时将当前有效钻石/超级会员的 `selectedAvatarFrameId` 设为其最高可用内置框，并把 `selectedAvatarFrameExpiresAt` 设为其当前会员到期时间（终身会员为空）；普通用户保持 `null`。迁移后的新获得/升级不自动佩戴。
5. 旧客户端继续按 VIP 推导框，无法理解用户取消佩戴。发布顺序必须为：
   - 后端兼容字段上线；
   - 新移动端上线并切换到服务端外观；
   - 当最低支持版本更新后，再决定是否移除旧推导逻辑。
6. 在过渡期，服务端无法阻止旧客户端按 VIP 自行画框；产品上“全局隐藏”对支持该功能的新客户端生效。发布说明必须明确最低客户端版本。

后端：

- 迁移结构、外键、索引和内置目录种子。

- 选中无资格/停用/过期头像框被拒绝。
