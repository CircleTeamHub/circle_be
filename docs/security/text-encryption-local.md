# 文字加密：本地开发联调

状态：2026-10-16，App、后端和管理员设备已接入；属于开发功能，不是上线验收。仅新发送的文字/文字引用加密。媒体、卡片、元数据、既有明文历史沿用原有策略。管理员是明确披露的解密成员，不能向用户宣称“只有聊天双方可读”。

## 已验证

- 真实 PostgreSQL + Nest HTTP 设备接口 + 实际 ChatService 发送事务；客户端使用同一个 MLS 模块。
- 首台设备登记；后续设备待批准；已有设备签名批准；撤销不可重新批准。管理员根密钥也不能换设备 ID 绕过撤销，数据库公钥唯一约束覆盖并发登记。
- 普通 App 与管理台 audience 隔离；聊天成员、设备状态、管理员当前 IM_READ 权限复查。
- 两个 App 设备、第三个获批 App 设备及管理员设备加入同一会话，均可解密；服务器仅保存信封密文。
- 文字/引用明文降级被拒绝；签名篡改、冒充发送者、旧 epoch、残留已撤销设备被拒绝。
- 撤销后先更新 MLS 成员与 epoch，再恢复发送；被撤销设备即使拿到新密文也无法解密。
- 提交已落库但 HTTP 回包丢失时，从加密日志中的待提交意图重试，不多推进一次 epoch。
- 同一批设备再加入第二个群聊，使用新的一次性 KeyPackage，不能复用已经消耗的私钥。
- 管理员读取密钥事件必须填写原因，审计中没有正文或私钥；当前权限撤销后不能继续发起读取。
- 原生 SQLite 日志由设备专属 SecureStore 密钥加密；浏览器 IndexedDB 日志由本机口令派生密钥加密，错误口令、并发覆盖和中断事务测试通过。
- App 普通缓存/outbox 仅接收密文，气泡明文不回写 Zustand；加密开发开关开启时暂停明文草稿自动保存，已加密会话的旧草稿会清除。
- 管理台主动解锁、锁定、后台自动锁定、账号切换及迟到结果清理测试通过。

## 本地启用步骤

1. 后端执行 `npm run prisma:generate` 和本地迁移。新增迁移 `20261017000000_text_encryption_devices` 和 `20261017001000_unique_encryption_device_key` 已应用到当前 localhost 开发库。不要对线上数据库执行本地联调脚本。
2. 后端开发环境设置 `E2EE_TEXT_ENABLED=true`；App 开发环境设置 `EXPO_PUBLIC_E2EE_TEXT_ENABLED=true`，重启相应开发进程。关闭开关只能暂停新启用，不能让已有加密会话降级明文。
3. 管理台的“聊天记录”页显示“管理员解密设备”。在将长期保管的浏览器中创建/解锁本机保险库，口令至少 12 个字符；推荐使用随机长口令。口令不发往后端。
4. 将该浏览器显示的 **公钥** 配置到后端 `E2EE_AUDIT_ROOT_PUBLIC_KEY`，重启后端，再点击“登记 / 发布加入密钥”。私钥和口令不得配置到服务器。
5. App：“设置 → 账号与安全 → 文字加密与设备”，逐台登记。新增设备先显示 PENDING，在已批准设备上核对完整公钥并批准，再在新设备上重新发布加入密钥。
6. App：“聊天信息 → 文字加密与设备”，通过当面或独立可信渠道逐一核对各设备及管理员设备的完整公钥。所有参与账号都必须有已批准设备和未使用的加入密钥。
7. 一对一会话可由任意在座参与者启用；群聊须群主启用且成员名单对成员可见。启用设备担任该会话的密钥管理设备。点击“开启文字加密”；其他 App 和管理员设备核对身份后加入/同步。
8. 正常聊天页发送文字。管理员按原流程填写访问原因查询记录，然后在已解锁设备点击“在此设备解密”；密文不能用服务器全文搜索。
9. 撤销加密设备后，密钥管理设备点击“更新会话设备与密钥”。在成员更新成功前后端会拒绝新文字发送。加密设备管理与现有登录设备管理目前是分开的操作。


`test-e2ee-local.ts` 只接受 loopback 数据库，创建随机 UUID 测试账号、两个会话和设备，开启独立临时 HTTP 监听；退出时清理自己的账号、注册表、会话和审计记录。它使用测试 JWT 签名密钥，不需要或输出真实用户的密码、token、私钥。测试的网络设备接口和 ChatService 使用真实数据库；外部媒体服务被替代为空操作，因此不等同于手机实机端到端 UI 验收。

共享源在 `circle-im/packages/e2ee`。管理台 `vendor/e2ee` 是 `npm run sync:e2ee` 生成的独立构建副本，`SOURCE.json` 记录源文件 SHA-256。更新共享模块后须同步，不能手改副本。

## 此开发版本的边界

- iOS/Android 完整 JavaScript 打包通过不等于真机 Hermes、Keychain/Keystore、生物识别及耗电验收；当前尚未完成真机双端 UI 验收。
- 固定 MLS 管理设备负责成员变更；管理设备丢失或被撤销会暂停该会话发送。管理员轮换、管理设备移交及恢复密钥/加密历史迁移仍需继续实现。
- 新加入设备没有加入前的 MLS 历史密钥；它不能自动获得早期历史。管理员设备必须从启用之初加入并保管本地密钥状态。不得声称所有新管理员设备都能自动读取全部历史。
- 当前开发日志的 inbox/outbox 各有 1,000 项容量保护，每个会话最多 64 台设备；还需实现分段加密归档、确认后 outbox 回收和长期容量测试，才能面向日常长期使用。
- 加密文字的编辑、复制、转发、引用原文、收藏和全文检索暂不开放，避免把明文导出到旧路径。可发送新文字、更正消息和撤回；媒体流程保持原有行为。
- App Web 加密入口会明确拒绝使用普通浏览器存储保存私钥；本阶段 App 面向原生客户端，管理台使用显式解锁的浏览器保险库。
- 隐藏成员名单的群和临时/客服会话不支持启用；不改变原有成员隐私设置。
- 上线前仍需独立协议安全审查、完整互操作测试、密钥恢复与轮换、负载测试和真机验收。当前保持开发功能开关，不应对外宣传为已完成生产级加密。
