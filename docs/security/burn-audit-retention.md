# 阅后即焚与管理员留存

- 单聊的新消息在对方首次已读时开始倒计时，重复回执不会延长；已经起算的历史消息保留原期限。群聊计时行为维持原样。
- 普通历史、搜索、同步、媒体与 APP 加密恢复仍按消息到期时间拒绝访问。焚毁事务先把当前正文/密文写入独立 `ChatBurnArchive`，再清空用户消息正文和编辑历史。旧版本已经清空的正文无法恢复。
- 留存期为消息原焚毁到期时间起180天，而不是扫描任务执行时间。首次部署之前已经焚毁的记录不回填。
- 后台统一“查看聊天记录”入口同时查询普通消息与留存记录；留存记录调用独立接口 `POST /admin/im/conversations/:id/archives/query`。必须填写原因、持有 `IM_ARCHIVE_READ`（默认仅 SUPER_ADMIN），事务内复核账号和授权并成功落审计后才返回内容。普通消息接口仍排除焚毁消息；后台仅对持有归档权限的账号合并展示两类结果。
- 附件保留在现有私有存储中，短时签名访问；笔记导入的引用锁保留到归档清理。归档到期后，每分钟的有界清理任务在同一事务中排队删除附件、释放引用、删除 AUDIT 恢复副本和正文。队列失败会回滚，后续任务重试；物理对象删除可能晚于访问截止。存储盘点把归档附件视为有效引用。
- 加密消息只留密文及已经授权生成的 AUDIT 恢复副本。后台必须使用已批准、具备该会话解密能力的设备；本改动不添加主密钥或绕过 MLS。没有相应密钥的历史密文无法凭留存解密。APP 恢复副本仍在焚毁时删除。
- 移动端单聊的阅后即焚提示明确告知平台留存180天。普通后台查询尚未已读消息时，只给本次展示一个焚毁时长的可见期限，避免之后已读而页面永久停留；需重新审计才能继续看。
- 数据库/对象备份的轮转策略需要单独配置；本任务的180天截止约束在线访问与主存储清理，不声称已删除离线备份或管理员自行保存的副本。

## 发布

1. 先合并基础后端 [#273](https://github.com/CircleTeamHub/circle_be/pull/273)、App [#294](https://github.com/CircleTeamHub/Circle_frontend/pull/294) 和后台 [#11](https://github.com/CircleTeamHub/circle_admin_web/pull/11)。本后端 PR 基于 #273 分支。
2. 维护窗口停止或排空全部旧后端写入、焚毁扫描和媒体清理任务，再执行 `20261019000000_read_started_burn_revision`、`20261019000100_pending_read_burn_index`、`20261019000200_burn_audit_archive`、`20261019000300_burn_media_reference_indexes` 四项迁移。第二和第四项含 `CREATE INDEX CONCURRENTLY`，不要将整批迁移额外包进一个事务。
3. 运行 `npx prisma generate` 并部署本后端版本，确认旧实例已全部退出。旧代码可能继续写入发送起算期限或删除应留存的媒体，不能长期混跑，也不能直接回滚到旧清理逻辑。
4. 再发布配套 App [#296](https://github.com/CircleTeamHub/Circle_frontend/pull/296)，使首次已读后的失效事件即时拉取新的 revision，并向用户展示180天审计留存说明。
5. 再发布后台 [#12](https://github.com/CircleTeamHub/circle_admin_web/pull/12)，统一展示普通与有权限访问的留存记录。昵称入口整理不依赖此 API。

本 PR 仅提交代码和迁移文件，未在开发库或生产库执行迁移；集成验证只运行在临时隔离 PostgreSQL 测试实例。

## 验证

后端定向 Jest 覆盖起算、归档权限、审计失败、媒体保留、清理及加密隔离。真实 PostgreSQL 验证使用独立测试库：

```sh
BURN_ARCHIVE_TEST_DATABASE_URL=postgresql://localhost/circle_burn_test NODE_ENV=test npx jest --config test/jest-postgres.json --runInBand
```

测试仅在数据库名包含 test 且 NODE_ENV=test 时运行，在独立 schema 建最小表，验证真实迁移触发器和实际起算 SQL，结束删掉测试 schema。不启动应用或连接现有业务数据库。

## 审查修复

- 私聊手动已读、清空即已读和客服自动已读共用同一事务内计时函数；自动回复同样等待对方首次已读。
- 用户媒体链接在会话共享锁下批量核对消息，签名的绝对截止时间不晚于焚毁期限；尚未起算时最多一个焚毁窗口，避免先发出的两小时链接跨过用户侧焚毁。重复键按各自授权期限签名，不复用普通消息的长授权。
- 管理员归档到期前检查活跃消息及其他留存归档的媒体引用，和发送路径共享对象键锁；已排队删除的对象不能被新消息重新引用。新增表达式索引支持引用检查。
- 重复焚毁扫描仅处理本事务真正返回的墓碑，不删除其他实例保留的附件；未获得清理租约的实例记录 skipped，不刷新成功心跳。
- 审计读取失败不删除恢复密文；全局清空先于焚毁扫描时保留待焚毁消息的 AUDIT 副本，撤回和普通非焚毁消息仍遵循原清理规则。

既有签名链接的发布边界：新版本限制的是新签发的用户授权，无法撤销旧版本已经发出的对象存储签名。若线上仍有旧的两小时媒体授权，在启用归档留存前，应先停止旧签名服务并等待最长两小时授权窗口耗尽；也可先单独回移限期签名修复、等待旧授权过期，再启用本批归档迁移。不能让旧的长授权与保留原对象的归档策略直接重叠。

- 未读私聊推送保持正常投递 TTL；已从发送起算的群消息仍按焚毁时长收紧。对已逻辑到期、尚未扫描的消息执行撤回时，数据库先捕获审计归档，再清空正文，避免通过撤回顺序绕过留存。
