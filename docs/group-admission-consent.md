# 群邀请与入群申请

独立群的成员资格只有在本人明确同意、且满足当前入群规则后创建。查看笔记群名片或二维码、发出邀请、提交待审核申请，都不会创建 ChatMember。

## 行为

- 笔记群名片先请求群资料与真实成员身份。已入群在原 tab 进入聊天；未入群查看资料并申请，待审核期间不能访问群消息。
- 邀请好友（包括建群时选择的好友）产生 INVITED 记录、私聊邀请卡片、联系人收件箱未读通知和离线推送。只有被邀请人能接受或拒绝。
- 独立群二维码先预览；只有新的 `/qr/tokens/:token/accept` 才表示接受。旧的 GROUP `join` 路径拒绝直接入群。
- 默认 `joinApprovalRequired=true`：群主或当前管理员发出的直接邀请，本人接受后直接入群，不重复审核；普通成员邀请和二维码接受后进入 PENDING，由当前群主或管理员审批。关闭审核后也必须先接受。名片申请始终待审核。直接邀请接受时重读邀请人的当前角色，已撤销管理员身份的邀请恢复群审核规则。
- `memberCanInvite`、`qrJoinEnabled`、`cardJoinEnabled` 分别控制成员邀请、二维码和名片申请。接受与审批时重读权限、邀请有效期、二维码撤销状态、好友/隐私关系及成员容量。
- 圈子群沿用入圈担保规则。普通邀请先处于 INVITED；本人接受后才进入原有担保/审批流程。原有担保人数快照不被后来的设置变化覆盖。
- 联系人群收件箱按群合并邀请、申请与已加入会话；使用记录最新更新时间显示状态，汇总该群未读数。群主管理页保留逐人的申请明细。
- 退群后的旧入群记录按真实座位映射为 LEFT，重新邀请或申请创建新记录；收件箱最新状态覆盖原群行，排除已退群的聊天缓存。旧详情再次申请跳转到新记录。退群清除本人的旧提醒并停止未发出的推送，晚到的旧入群任务不重发。
- 独立群和圈子群进群、退群均不再产生聊天系统提示；成员权限/房间同步和群日志仍执行。
- 审核完成后清除所有审核接收人的待审提醒、取消尚未发送的待审推送，过时任务不再补发。入群成功只通知申请人，不另行通知群主和管理员。
- 只查看详情会清除本人对应通知未读，不会自动接受。收到圈子邀请归入联系人收件箱，不受圈内动态的离线提醒开关门控。
- 邀请卡片是服务端消息类型，客户端不能伪造发送。操作后重查状态；无法确认的网络结果不自动重试写操作。

## 持久化与并发

GroupAdmission 保存状态，GroupAdmissionDelivery 在同一事务内保存卡片/通知及成员广播投递任务。通知与推送 outbox 按任务 id 去重，私聊卡片按 admission id 去重，广播失败可重放。圈子邀请有独立的 consentNoticeRequired/DeliveredAt/Attempts，接受或拒绝后也继续补投递未送达的卡片；失败任务按尝试次数轮转，避免阻挡新邀请。

独立群使用会话行锁串行化接受、审批、容量和群策略；数据库 partial unique index 保证同一群、同一申请人最多一条进行中的记录。圈子接受使用 INVITED 条件更新，避免覆盖并发拒绝。新成员和重新入群者继承当前消息水位，不能看到入群前的记录。收件箱群资料、用户摘要和人数按页批量查询。
